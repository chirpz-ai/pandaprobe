Run evaluations against traces or sessions already captured in your project. Use the dashboard for interactive review, the API or CLI for automation, and monitors for recurring checks.

## Prerequisites

- **Captured traces** in the project you want to evaluate. Start with the [Tracing Quickstart](/tracing/get-started/quickstart) if needed.
- **A shared `session_id`** for related traces when running session evaluation.
- **Project access** through the dashboard, or an API key and project name for API and CLI requests.

<Note>
  PandaProbe Cloud manages the evaluation LLM infrastructure. Self-hosted deployments need provider credentials configured on the server for judge and embedding calls.
</Note>

## Configure a run

1. Choose **traces** or **sessions** and select the matching [metrics](/evaluation/metrics).
2. Select specific IDs, or use filters to define the target set. Filtered runs can sample a fraction of matches.
3. Optionally choose a judge model. Session runs also support custom signal weights.
4. Submit the run and review its progress and scores when processing finishes.

Each score includes a value, computation status, reason, and metadata. A completed run can contain failed computations; check `failed_count` and individual score statuses when reviewing results.

## Choose a setup method

| Method | Use when |
| --- | --- |
| [Dashboard UI](/evaluation/setup/run-eval-ui) | You want to select data, configure metrics, and inspect results visually. |
| [API](/evaluation/setup/run-eval-api) | Evaluations belong in an application, notebook, or custom service. |
| [CLI](/evaluation/setup/run-eval-cli) | You work from a terminal or shell-based CI workflow. |
| [Scheduled monitors](/evaluation/setup/scheduling) | You want recurring checks with saved metrics, filters, and sampling. |
